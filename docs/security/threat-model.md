# Threat Model

## Scope and trust boundaries

The engine accepts untrusted requests, website URLs, task text, planner-provider output, discovered URLs, website HTML/JSON-LD, extracted values, export values, document metadata, browser responses, redirects, and SSE parameters. Durable jobs, plans, records, validation runs, exports, generated files, outbox commands, and events are server-owned data. The application has no production identity provider in this repository; the development principal is intentionally limited to `APP_ENV=development`.

| Threat class | Attack surface and attacker capability | Existing or Phase 11 control | Verification | Residual risk / mitigation |
| --- | --- | --- | --- | --- |
| SSRF, localhost, private/cloud metadata access | URL input, discovered links, redirects, browser subresources | HTTP(S)-only admission; credential/fragment rejection; public-IP DNS policy; same-domain browser policy; every route request rechecked; public port allowlist | URL and browser-policy tests cover loopback, private ranges, malformed forms, redirects, resolver errors, and port rejection | DNS may change after a browser policy check; production browser egress firewall/DNS pinning remains required. |
| DNS rebinding | Host resolves publicly then changes during browser connection | Per-navigation and per-resource DNS checks, redirect revalidation, constrained origin scope | Browser policy resolver tests | Application code cannot pin Chromium’s socket destination; deny private egress at network layer before production. |
| Crawl and browser exhaustion | Link/sitemap explosions, redirects, oversized responses/downloads, crashes, cancellation | Server-owned discovery/browser page, depth, redirect, lifetime, response, download, context, timeout, retry, and cancellation limits | Discovery, browser policy/orchestration, and worker recovery tests | Runtime quotas and browser sandboxing are deployment prerequisites. |
| Prompt injection and hostile model output | User task text and provider responses | Immutable source/outputs/limits; strict canonical planner schema; no model-issued browser command path; bounded provider retries | Planner schema/model/orchestration tests | Provider trust and prompt confidentiality require production key controls. |
| XSS and stored XSS | Extracted values, result rows, files, document HTML | React text rendering; no unsafe HTML primitive; escaped standalone HTML documents; controlled downloads | Frontend result tests and document tests include script-like text | User-supplied custom templates are intentionally unsupported. |
| CSV/XLSX formula injection | Formula-like normalized values | Leading apostrophe for `=`, `+`, `-`, and `@` in spreadsheet writers only | Export service tests | JSON deliberately retains original values. |
| Filesystem/storage traversal and leakage | Artifact keys, filenames, export/download paths | Opaque generated keys; resolved-root check; allowed MIME types; 0600 files/0700 root; atomic temp write; owner joins for file metadata/downloads | Storage and authorized-files lifecycle tests | Local store is development-only; production object storage and retention operations remain future deployment work. |
| Authentication, authorization, IDOR, SSE leakage | Jobs/results/files/pages/events and guessed IDs | Every protected projection uses job/project-owner lookup; file downloads repeat owner lookup; SSE authorizes before event stream | API, results, export lifecycle, and ownership tests | Development headers are not production authentication; this is a production blocker. |
| API abuse and malformed input | Mutating request bodies, pagination, repeated requests | Pydantic constraints, request-body ceiling, pagination clamp, idempotency keys, process-local sliding-window limiter, safe error envelope | API, schema, and Phase 11 control tests | Shared edge/Redis rate limiting is required for multi-instance production. |
| Queue and worker integrity | Redis DSN, duplicate delivery, lease expiry, failures | Transactional outbox, unique operation keys, skip-locked dispatch, leases, bounded retry classification, redis DSN preserves TLS/auth credentials | Lifecycle/recovery and queue security tests | Redis availability, TLS certificates, and observability are deployment prerequisites. |
| SQL, command, and code injection | ORM paths, shell/eval/import paths, templates | SQLAlchemy parameter binding; no production shell/eval/pickle/dynamic code execution; fixed document renderers | Repository static audit and integration tests | Test-only dynamic imports are not production execution paths and should be simplified later. |
| Secrets, logs, and errors | Configuration, logs, exception responses | `.env.example` uses placeholders; generic API error envelopes; correlation IDs; logs omit request body/headers | Source-only secret scan and error-contract tests | External secret management and log retention/redaction policy are deployment prerequisites. |
| Dependencies and container/CI supply chain | Node/Python lock/manifests, Docker, workflows | Patched PostCSS/Sharp transitive overrides; dependency audit; static Docker review; no repository workflow files | `pnpm audit --prod`, `pip check`, manifest review | ESLint deprecation and CI policy enforcement remain low-risk follow-up items. |

## Data retention

The current durable schema retains canonical plans, normalized records, bounded evidence, validation summaries/findings, event history, and generated-file metadata. Local artifacts persist until deleted by an external operational process. Raw website execution is limited to browser artifacts and extraction payloads already modeled by earlier phases. A retention scheduler is intentionally not introduced in Phase 11; production retention and privacy policy are required before launch.
